## 阶段一：目录归位 + CSS 外置（低风险，纯移动零逻辑改动）

**目标**：消除顶层平铺与 index.html 黑盒；所有 import 路径同步更新；行为零变化。

### 1.1 顶层文件归位
```
新建目录：
services/          ← self_repair.py / scheduler.py / version_store.py /
                     conversations.py / knowledge_ops.py / study_engine.py /
                     learn_capture.py / batch_flow.py / rule_check.py
desktop/           ← close_guard.py / tray.py
core/              ← config_store.py（阶段二再拆 core_utils）
llm_client.py 保留原位（被引用面广，风险大收益小）
```
**import 更新**（全局替换，每处验证）：
- `import self_repair` → `from services import self_repair`（及 `self_repair.xxx` 调用点）
- `import scheduler` → `from services import scheduler`
- 其余同理；`close_guard`/`tray` → `from desktop import ...`
- **兼容层**：每个旧模块位置留 3 行转发壳（`from services.self_repair import *`），防遗漏的 import 点炸掉——回归全绿后下一版删除

### 1.2 CSS 外置
- index.html 的 `<style>` 全文（~1000 行）抽到 `css/style.css`
- index.html 头部加 `<link rel="stylesheet" href="/css/style.css">`
- **静态文件路由确认**：Flask 需挂 /css/ 静态目录（backend 现有 static 处理方式需适配——用 `send_from_directory` 或 blueprint static_folder）
- **build.py 同步**：dist 拷贝清单加 css/
- 完成后跑 `tools/check_frontend.py`（div/id/CSS 检查需适配新路径——check 脚本读 style.css）

### 1.3 验收
- [ ] 196+ 项回归全绿
- [ ] `check_frontend.py` 通过（改造成读 css/style.css）
- [ ] 打包冒烟：启动 → 设置/工作台/聊天/自修复页全过一遍
- [ ] git diff 审查：无逻辑行变化（纯移动/重命名/import）

**回滚**：整阶段一个 commit，revert 即回。

## 阶段三：模块热更新（预研暂缓，暂不实施）

单文件 exe + PyInstaller 冻结机制下，"只更新某模块"需要：
1. 外置补丁目录（如 `mods/<模块名>.py`），启动时自定义 import hook 优先加载
2. 模块版本清单与依赖校验（防止补丁和主包版本错配）
3. 签名/校验机制（防篡改）

**不建议现在做的理由**：复杂度高（自定义 import 系统是 bug 温床）、与单文件分发模式冲突、当前"一键打包 2 分钟"已足够顺滑。**触发条件**：未来若出现"模块更新频繁但主包稳定"的真实需求再立项。

## 执行节奏与风险控制

| 阶段 | 预计会话 | 风险 | 关键护栏 |
|---|---|---|---|
| 一 | 1 次（~1.5h） | 低 | 纯移动零逻辑；转发壳兜底；git diff 审查 |
| 二 | 1-2 次 | 中 | 逐模块搬（不是一把梭）；每次搬完回归；转发壳保 import 兼容 |
| 三 | 暂缓 | 高 | 触发条件未到 |

**贯穿纪律**（沿用既有修复纪律）：
- 每步跑 `pytest` 全量 + `tools/check_frontend.py` + 打包冒烟
- 移动/删除文件后必跑结构校验（此前 index.html 三次结构事故的教训）
- 单实例/托盘/退出路径等 os 级功能每阶段手动冒烟（回归覆盖不到 GUI 层）

- 不做微服务/进程拆分（单机桌面软件，没必要）
