## 一、代码 / 静默失效线

**A1｜F821 硬门禁在 pyflakes 缺席时报绿**（P0，**已核实并已修**）
证据 `build.py:726-740`：`except FileNotFoundError → pyflakes_out=None → return 0`、
`except Exception → return 0`，且**从不看 `returncode`**；调用点 `if n_f821: return` 把 0 当通过。
出事场景：换机器 / venv 缺 pyflakes / pyflakes 自身崩溃时，v1.0.588 一次性扫出的那 7 类
「NameError 被 `except Exception` 吞成功能静默失效」整类回归全部门禁失效且绿灯发货。
修法：返回 -1（没跑成=失败），并校验 returncode 只接受 0/1。锁：
`tests/test_v626_audit_fixes.py` 三条（未装 / rc=2 崩 / 正常有 finding 仍非零）。

**A2｜月报批审 resume 把整批"没取到链接"的单据当已完成跳过**（P0，**已核实并已修**）
证据 `services/batch_flow.py` resume 段：判重键 `(r.get("url") or "")`。有一类单据取不到详情
链接（走"回退前台点击"，见 `:878` 注释），其 url 恒为空串；断点里存在任意一条这种
green/red → `"" in _done_keys` 恒真 → 本轮**所有**无链接项被过滤掉，而报告总数守恒，
看不出漏审。修法：抽 `resume_key/resume_partition`，无链接项按标题判重，
并处理"断点记录里叫 title、待办链接里叫 text"的字段名不统一（这一条是我复核时补的，
子代理只发现了空串那半）。锁 4 条（含"旧形状会 todo=[] "的对照断言）。

**A3｜「绝不自动点同意/提交」的红线只到提示词层**（P1，**已核实事实，未动**）
证据：`security_ops.py:202 _ALWAYS_ASK` 只有 `run_audit_flow(auto_approve)`；
`executors.py:779-809` 的 JS 危险名单有 `\.submit\s*\(` 但**没有 `.click(` / `dispatchEvent`**；
全项目 grep 不到任何按按钮文案（同意/提交/审批通过）设的拦截。
结论：`wecom_run_js("…querySelector('[data-btn=approve]').click()")` 在 auto 档 /
`sched-`·`study-` 后台会话可全程无审批执行；`click_wecom_element` 点"同意"同样不被工具层拦。
这不是回归——是红线本来就没落到代码层，靠提示词与 `run_audit_flow` 参数守。
**要不要收口需要你先定口径**（收法：把 `.click(`、`dispatchevent` 加进 JS 名单 +
给 click 类工具加"按钮文案命中审批词 ⇒ 无论档位一律转人工"的闸门）。因为会改变
批审自动化行为，我不擅自动。

**A4｜跑课链路把 auto_loop 的两条自愈短路成死代码**（P1，**待核**）
子代理证据：`services/study_engine.py:554` 收到 `done` 即 break，
而 `agent/auto_loop.py:83-92`（流式中断→从断点自动续跑）与 `:95-113`（RESULT: FAIL→开新会话）
在该路径永不触发，实际只剩外层 `MAX_ATTEMPTS=3` 的全新会话。
影响：跑课遇到流断是"重开新会话"而不是"从断点继续"，已完成题的进度只能靠台账文本承接。
待核什么：需要确认 study_engine 自己有没有等价的断点续跑（它确实现了 RESULT 三态与
`_prune_zn_windows`），若有，则本条降级为"两条自愈通道口径不统一"而非"没有自愈"。

**A5｜三处债**（P2）
- `wecom_bridge/cdp_client.py:39,56-60 _WS_POOL` 无淘汰：长会话按 targetId 单调增，
  页面关闭后的 entry（含 Lock 与死 socket）永不回收；全项目零清理、测试零覆盖。

- 后台判定前缀 `("sched-","study-")` 手抄 5 处（`loop.py:141/632`、`session.py:189/190/198`）
